    from datetime import datetime, timedelta, timezone

    from crash_detector.staleness import StalenessWindow, FreshnessEvidence
    from crash_detector.witness.panel import Agrees
    from crash_detector.serving.witness_resolver import render_panel

    # PL-Y1  which of the three values are slotted?
    for cls in (StalenessWindow, FreshnessEvidence, Agrees):
        print(cls.__name__, "__slots__" in vars(cls))

    now = datetime(2026, 8, 19, 12, 0, 0, tzinfo=timezone.utc)
    win = StalenessWindow(seconds=600.0)
    ev  = FreshnessEvidence(as_of_utc=now - timedelta(seconds=5), observed_at_utc=now, window=win)
    a   = Agrees(divergence_measure=0.01, as_of_utc=ev.as_of_utc, freshness=ev)

    # PL-Y2  inject an UNDECLARED attribute — boundary 3 says slots make this impossible
    for target in (win, ev, a):
        object.__setattr__(target, "an_attribute_nobody_declared", 1e18)

    # PL-Y3  overwrite DECLARED fields with a decade-old instant, then render
    decade = datetime(2016, 8, 21, 12, 0, 0, tzinfo=timezone.utc)
    object.__setattr__(a,  "as_of_utc", decade)
    object.__setattr__(ev, "as_of_utc", decade)
    render_panel(a)

PREMISE CONFIRMED, AND CONFIRMED MORE STRONGLY THAN IT WAS STATED.

Boundary 3 of the CD-AC-005 freshness closure currently reads, in all three CD-RULE-004
places, "Both values use ``__slots__``, so an UNDECLARED attribute cannot be injected", and
generalises in its own first sentence to "every frozen value in Python AND IN THIS
REPOSITORY". PL-Y1 shows the two values it names ARE slotted and `Agrees` IS NOT. PL-Y2 does
not stop at the class attribute — it performs the injection the boundary says is impossible,

FALSE there, on the very generalisation the boundary makes.

PL-Y3 carries it to the sentence the Product Owner forbade. A constructed, lawful `Agrees`

WHAT IS NOT ESTABLISHED, so it is not over-read: this does not make the increment-5 closure
wrong. The closure's claim is that a decade-old row cannot produce an `Agrees` BY ANY ROUTE
INTO ANY RESOLVER, and PL-Y3 does not use a route into a resolver — it forges an already
