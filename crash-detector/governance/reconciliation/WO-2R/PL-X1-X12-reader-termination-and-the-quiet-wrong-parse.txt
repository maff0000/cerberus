PL-X9 — THE DECISIVE ONE. THE BACKSTOP IS NOT DECORATIVE.
--------------------------------------------------------------------------------------------

The repair claims TWO independent layers: `_advance`, which refuses a delegated cursor that did
not move; and a per-loop iteration budget which "exists so that a future edit which breaks that
fails CLOSED". The budget branches carry `# pragma: no cover` and the seat DISCLOSED against
itself (CD-ENG-READER-F07) that no input can reach them, so they are proved only by monkeypatch.

A backstop nobody has seen fire is an argument, not a layer. So the Project Lead broke RULE 2
in the source itself, on a throwaway extraction of 253c38b: the `_advance` call in the
sequence-item merge loop was DELETED and the cursor adopted directly, exactly as it was at
f22d120 — then PL-X5 was re-run.

    RESULT: REFUSED, not hung.
    "line 2: the sequence-item merge loop made no progress past '- nested' within its iteration
     budget. This is an internal invariant failure in this reader, not a defect in the document;
     it refuses so that a caller gets a verdict."

WITH `_advance` REMOVED ENTIRELY, THE READER STILL TERMINATES. The two layers are genuinely
independent, and the one the seat could only justify by argument has now been OBSERVED doing the
job it was written for. This is the first declared-unreachable backstop on this project to be
proved by execution rather than by reading.
